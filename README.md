## Theory

A regular expression is a sequence of symbols that defines a search pattern over strings. It describes a regular language - the same class of languages recognized by finite automata and generated by regular grammars. The standard operators are concatenation (writing symbols next to each other), alternation (`|`), and three repetition forms: `*` (zero or more), `+` (one or more), and `?` (zero or one). Bounded repetition such as `{n}` allows specifying an exact count.

Regular expressions are used in lexical analysis, input validation, search-and-replace operations, log parsing, and language definition. A regex engine first parses the pattern into a tree structure, where each node represents one operator. Once parsed, the same tree supports two opposite tasks: matching strings against the pattern, or generating strings that conform to it. This lab focuses on generation.

The structure of the parser follows the operator precedence of regex syntax. Alternation has the lowest precedence, concatenation is implicit and has middle precedence, and the repetition operators bind tightest to their atom (a literal or a parenthesized group). A recursive descent parser respects this precedence by calling its sub-parsers in the right order.

## Objectives

* Build a parser that converts an arbitrary regex string into an abstract syntax tree, without hardcoding any pattern-specific logic.
* Implement a generator that walks the AST and produces random valid strings matching the regex.
* Limit unbounded repetition operators (`*`, `+`) to a maximum of 5 iterations to avoid extremely long outputs.
* Implement an explainer (bonus) that prints the processing sequence the generator follows for a given regex.
* Apply the implementation to the three Variant 3 regexes and verify the generated strings conform to each pattern.

## Implementation Description

### RegexParser Class

The `RegexParser` is a recursive descent parser that converts a regex string into a tree of tuples. Each node carries a kind tag (`literal`, `concat`, `alt`, `star`, `plus`, `question`, `exact`) and its child nodes. The grammar has three levels: alternation at the top, concatenation in the middle, and a repetition operator applied to an atom at the bottom. An atom is either a single character literal or a parenthesized sub-expression, which recurses back into the alternation parser.

```python
def parse(self):
    return self._parse_alternation()

def _parse_alternation(self):
    left = self._parse_concat()
    if self._peek() == '|':
        options = [left]
        while self._peek() == '|':
            self._consume()
            options.append(self._parse_concat())
        return ('alt', options)
    return left

def _parse_repeat(self):
    atom = self._parse_atom()
    nxt = self._peek()
    if nxt == '*':
        self._consume()
        return ('star', atom)
    if nxt == '+':
        self._consume()
        return ('plus', atom)
    if nxt == '?':
        self._consume()
        return ('question', atom)
    if nxt == '{':
        self._consume()
        num = ''
        while self._peek() != '}':
            num += self._consume()
        self._consume()
        return ('exact', atom, int(num))
    return atom
```

### RegexGenerator Class

The `RegexGenerator` walks the AST produced by the parser and assembles a string. Literals contribute their character. Concatenations join the outputs of their children. Alternations pick one branch at random. The repetition operators decide how many copies of their child to emit: `*` picks 0 to 5, `+` picks 1 to 5, `?` picks 0 or 1, and `{n}` always emits exactly n. Each call to `generate()` produces a fresh independent string.

```python
def _gen(self, node):
    kind = node[0]
    if kind == 'literal':
        return node[1]
    if kind == 'concat':
        return ''.join(self._gen(c) for c in node[1])
    if kind == 'alt':
        return self._gen(random.choice(node[1]))
    if kind == 'star':
        n = random.randint(0, REPEAT_LIMIT)
        return ''.join(self._gen(node[1]) for _ in range(n))
    if kind == 'plus':
        n = random.randint(1, REPEAT_LIMIT)
        return ''.join(self._gen(node[1]) for _ in range(n))
    if kind == 'question':
        return self._gen(node[1]) if random.choice([True, False]) else ''
    if kind == 'exact':
        return ''.join(self._gen(node[1]) for _ in range(node[2]))
    return ''
```

### RegexExplainer Class (Bonus)

The `RegexExplainer` is a separate walker over the same AST. It does not produce a string - it documents the steps the generator would take, ordered by the structure of the parse tree. Output is indented to reflect nesting and uses operator-specific phrasing for each node kind.

```python
def _walk(self, node, depth):
    indent = '  ' * depth
    kind = node[0]
    if kind == 'literal':
        self.steps.append(f"{indent}Output literal '{node[1]}'")
    elif kind == 'concat':
        self.steps.append(f"{indent}Concatenate {len(node[1])} parts:")
        for c in node[1]:
            self._walk(c, depth + 1)
    elif kind == 'alt':
        self.steps.append(f"{indent}Choose one of {len(node[1])} alternatives:")
        for c in node[1]:
            self._walk(c, depth + 1)
    elif kind == 'plus':
        self.steps.append(f"{indent}Repeat 1 to {REPEAT_LIMIT} times:")
        self._walk(node[1], depth + 1)
    # ... other operator branches follow the same pattern
```

### Variant 3 Regex Definitions

The three patterns assigned to Variant 3 are:

```
1. O(P|Q|R)+2(3|4)
2. A*B(C|D|E)F(G|H|i){2}
3. J+K(L|M|N)*O?(P|Q){3}
```

The original handwritten notation uses `²` and `³` superscripts for exact repetition. These translate directly into the `{n}` syntax used by the parser.

## Conclusions

The lab demonstrated that a regex can be processed cleanly in two stages: parse to AST, then walk the AST. Keeping these stages separate kept the code small and made the bonus task trivial - the explainer is just a second walker over the same tree, sharing no logic with the generator. The dynamic interpretation requirement is satisfied by the parser alone, since the same code handles all three Variant 3 regexes and would handle any other regex built from the same operators without modification.

The main difficulty was deciding how to interpret the superscript repetition notation (`²`, `³`) from the original task image. Mapping them to `{n}` exact-count syntax produced outputs consistent with the lab examples and is the natural ASCII equivalent. A second smaller decision was how to interpret `(P|Q){3}` - whether each of the three positions picks independently or all three share one chosen letter. Standard regex semantics (independent picks) was used, which matches what a real regex engine would produce.
